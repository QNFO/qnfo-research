## Post 1: The Thesis (Wed Jun 4, 9:00 AM ET)

The bottleneck to scientific productivity isn't brilliance. It's throughput.

A postdoc isn't 20× smarter than a professor — they're 20× faster at executing tasks. What if an LLM could close that gap?

I've been testing a structured 5-phase protocol. Preliminary self-experiments across two domains suggest 25×–90× speedups — a day of focused human direction producing what would take months.

Result: "The Force-Multiplier Playbook" — a free, open-access whitepaper. Full methodology, 5 reusable prompt templates, verification protocol, and an honest limitations section.

## Post 2: The How-To (Fri Jun 6, 9:00 AM ET)

The entire force-multiplier stack is 4 components:
1. LLM with file access
2. Code execution (Python)
3. Git for version control
4. Markdown + LaTeX

That's it. No Docker. No API keys. No multi-agent frameworks. One conversation thread.

The 5-phase protocol: Define → Delegate → Execute & Iterate → Verify → Synthesize.

5 reusable prompts cover the full pipeline. Every prompt is copy-pasteable in the repo. Every phase documented with real examples.

## Post 3: The Limitations (Wed Jun 11, 9:00 AM ET)

Honesty about limitations builds more credibility than confidence without evidence.

The Playbook includes a full section on what the protocol CANNOT do:
• No wet lab work
• No fieldwork or human subjects
• Verification gates reduce risk, don't eliminate it
• Speedup numbers are preliminary self-experiments
• Domain generality untested beyond physics and linguistics
• First-time users will see smaller gains

The strongest section of any methodology paper should be the one that says "here's where this breaks."

Looking for researchers in biology, pure math, social science, and philosophy to test and report results.
