## Build-gate note (kaizen)

The v0.3 PDF initially reported `U+FFFD=1` on the binary byte scan, and `pdftotext` showed FFFD at dash positions. Diagnosis: (1) the raw-byte hit at offset 21,458 lies **inside a FlateDecode-compressed stream** — decompressing all 58 streams yields **0 FFFD/FFFF in the actual PDF content** (the 3-byte sequence occurs in compressed entropy by chance; false-positive class for PDFs > ~1 MB); (2) the decoded-text dash FFFDs are a Chrome PDF ToUnicode **extraction artifact** (glyphs render correctly; only copy-paste mapping degrades — present in all prior versions too). The source `.md` and pre-inline `.html` both scanned **0 U+FFFD**. Recommended kaizen: the mojibake gate should decompress Flate streams before scanning (or scan only source artifacts); the raw-byte scan on compressed PDFs is authoritative only below ~1 MB. The title-block middle dots (U+00B7) were replaced with `|` separators as part of the investigation (harmless typography change).
